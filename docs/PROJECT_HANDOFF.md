## Почему исправляем генератор Nginx

В исходном Stack CLI `v1.2.3` есть директива размера тела для маршрута `/storage/v1/`. Загрузка из рабочего пространства идёт через `/api/pea/…/versions` и попадает под другой блок Nginx. Поэтому одного совпадения `client_max_body_size` при поиске по конфигурации недостаточно. После сборки нужно проверить значение именно для запроса версии и убедиться, что оно сохраняется после очередной синхронизации оператором. В архиве для этого маршрута принята локальная правка с `100m`. Порог относится к телу HTTP-запроса, включая multipart. Контрольный опыт — файл около 5 МБ. [Генератор Nginx](https://github.com/stack-cli/stack-cli/blob/d7eed86d474bdf56059625b322e59383bf2ce380/crates/stack-cli/src/services/nginx.rs) · [Обработчик загрузки в адаптере](https://github.com/Dach1980/bionic-personal-expert-ai/blob/46b01dd7f6ae2cecc4a24f762805e49a8f4fafdd/crates/web-server/handlers/pea.rs)
